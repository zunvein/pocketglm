# v0.2.1-alpha

Fix release for the Token Farm falling back to a single token.

## Fixed
- **Token Farm: "Bridge refused the batch (HTTP 422 … slot 42 is not the device IP)".**
  The bridge compared payload slot 42 with the IP the device service reported
  and refused the visit when they differed. On a phone they can legitimately
  differ (dual-stack IPv4/IPv6, mobile carrier NAT), so good visits were being
  thrown away and only the one genuine token was saved. That check is gone.
  The server-timestamp slot and the probe-log tail (entries 93/94) still gate
  the layout, and minted tokens are still verified against Aliyun before they
  enter the pool.
- Minting now keeps slot 42 exactly as the genuine token carried it instead of
  overwriting it with the session IP.

## Diagnostics
- When slot 42 and the session IP differ, the bridge log line for the mint now
  says so without printing any address: `ip-slot=ipv6 session-ip=ipv4
  session-ip-found-at=<slot or none>`. Copy the logs after a farm run if
  batches are still rejected by Aliyun (`minted=rejected`).

## Known limits
Same as v0.2.0-alpha. If Aliyun rejects the minted batch because the changed
slot mattered, the farm still saves the genuine token and reports it.
