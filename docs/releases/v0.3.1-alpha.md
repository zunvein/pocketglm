# v0.3.1-alpha

For phones on networks that cut the connection to chat.z.ai.

## Fixed
- **Account token in error messages.** When the bridge could not reach Z.AI, the
  error text included the full request URL, and that URL carries the account token
  in its query string. It showed up in the Chat tab and would have been sent to any
  API client. Network errors are now reported without the URL. If you saw such an
  error with a token in it, sign that account out and in again.
- **Token Farm on a blocked network.** The farm used to run its script on the
  browser's error page and print `Cannot read properties of null`. It now stops at
  once and says that chat.z.ai could not be loaded, with the browser's reason.

## New
- **Bypass blocking** (Home tab, off by default). Some networks answer the first
  packet of a secure connection that names chat.z.ai with a reset
  (`connection reset by peer`). With the switch on, the bridge sends that first
  packet in two pieces, and it runs a small local proxy (127.0.0.1:3002, HTTPS
  only) so the Token Farm and the sign-in page get the same treatment.

## Known limits
- Not proven on a real blocked network. It helps only when the block looks at the
  site name in the first packet. If it does not help, the block is on the address
  itself or on later packets, and only a VPN or a proxy will work.
- Changing the switch restarts the bridge.
