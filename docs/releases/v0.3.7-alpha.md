# v0.3.7-alpha

Farming no longer throws a whole visit away because the device session and the
token did not line up.

## Fixed
- **`Bridge refused the batch (HTTP 422: harvest rejected: template layout
  differs: slot 87 is not the server timestamp)`** — the visit was captured but
  the batch was refused, so 60 mints collapsed into "single token saved".
  A page load can register the device more than once (the site starts its own
  captcha, the app starts a second one), and the token is sealed against
  whichever registration came last. The farm used to keep only the **first**
  Log1 body it saw, so whenever those two differed the visit was lost. The farm
  now keeps every distinct Log1 body of the visit (up to 4) and the bridge mints
  from the one that actually seals the token.
- **The token's own server timestamp now wins** when it is within 30 minutes of
  the captured session. It is the copy Aliyun sealed, so it is the truth; the
  old check treated any difference as "wrong phone" and refused the batch.
- A late Log1 (the one that matters) could arrive a moment after the token; the
  farm now waits 1.5 s for it instead of settling instantly.

## Changed
- The farm log says which session was used and how far apart the timestamps
  were: `Minted batch verified by Aliyun: 61 tokens added, pool now 61 (session
  2/2, ts-skew +4127ms)`, plus `Sending 2 device sessions; the one that seals
  the token is used` when a visit produced more than one.
- The bridge accepts `log1s` (array) next to `log1`, and the request size limit
  went from 512 KB to 1 MB.

## Known limits
- A skew larger than 30 minutes is still refused: that is a different
  registration, and minting from the pair produces tokens Aliyun rejects.
- When Aliyun refuses the minted batch, only the phone's own token goes into the
  pool — the batch is dropped on purpose.
